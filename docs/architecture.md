# Карта архитектуры проекта

Этот файл описывает **текущее расположение кода и основные точки расширения**. Правила разработки и обязательные ограничения находятся в `AGENTS.md`. При расхождении с этой картой сначала сверяйся с фактическим кодом. Файлы в `.workai/plans/` — планы работ, а не гарантированное описание реализованного состояния.

## Структура верхнего уровня

| Путь | Назначение |
|---|---|
| `main.py` | Создание FastAPI-приложения, подключение статических файлов и агрегированного роутера. |
| `api/routers/` | HTTP/UI-адаптеры: принимают запрос, преобразуют ввод/вывод и вызывают логику приложения. Здесь не размещается основная логика возможностей. |
| `modules/` | Функциональные возможности продукта, сгруппированные по назначению или сервису. Ядро должно иметь вызываемую из Python точку входа и не зависеть от FastAPI. |
| `shared/` | Общие инфраструктурные компоненты и утилиты, которые действительно используются несколькими возможностями. Это не место для логики, специфичной одной функции продукта. |
| `scenarios/` | Кодовые сценарии, которые координируют несколько функциональных модулей через их Python-точки входа. Сейчас содержит заготовку реестра, но рабочих сценариев в нём нет. |
| `config/` | Общая конфигурация приложения. Настройки конкретной возможности или сервиса хранятся рядом с её кодом. Секреты читаются из окружения; не записывать их в документацию. |
| `tests/` | Автоматические тесты и отдельно расположенные ручные инструменты запуска. |
| `templates/`, `static/` | HTML-шаблоны и статические ресурсы пользовательского интерфейса. |
| `worksheets/`, `sources/` | Рабочие таблицы и исходные данные, используемые некоторыми операциями. Не считать их Python-пакетами. |
| `temp_files/` | Каталог временных результатов; создаётся или используется во время работы приложения. Не хранить в нём исходный код. |

## Текущие функциональные пакеты

### `modules/xmlriver/`

- `service.py:run_module` — общий программный запуск XMLRiver-возможности; проверяет входные данные и конфигурацию, затем вызывает функцию из реестра.
- `registry.py` — сопоставляет идентификаторы `frequency`, `popular`, `serp` с функциями сбора данных.
- `xmlriver_frequency.py`, `xmlriver_popular.py`, `xmlriver_serp.py` — реализация отдельных операций с XMLRiver.
- `settings.py` — настройки именно XMLRiver.
- `export.py` — формирование XLSX-результатов.
- `api/routers/xmlriver.py` — HTTP-адаптер: принимает пользовательский ввод, вызывает сервис, возвращает результат или файл.

Для прямого вызова из другого Python-кода используй `modules.xmlriver.service.run_module`, а не HTTP-запрос к собственному приложению.

### `modules/relevance_analyzer/`

- `service.py:run_analysis` — публичный вход для прямого Python-вызова; принимает проверенную конфигурацию и возвращает объект `Relevance` с рассчитанной статистикой.
- `config_input.py` — чтение исходного TXT-формата и JSON-конфигураций.
- `relevance.py`, `text_analyzer.py`, `morph.py`, `stopwords.py` — независимое от FastAPI ядро анализа и нормализации.
- `export.py:export_xlsx` — формирует четыре XLSX-отчёта; строки экранируются от формул.
- `api/routers/relevance_analyzer.py` — веб-адаптер запуска и скачивания ZIP-архива; внешние URL и перенаправления проверяются перед загрузкой.

Для Python-сценария вызывай `modules.relevance_analyzer.run_analysis(config)` напрямую. Веб-путь: `/relevance-analyzer` → `run_analysis` → четыре XLSX-файла в ZIP.

### `modules/openai_api/`

- `service.py:chat_completion` — публичный независимый от FastAPI клиент OpenAI Chat Completions; принимает OpenAI-совместимый формат, отправляет HTTPS-запрос и возвращает JSON API.
- `settings.py` — читает `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` и `OPENAI_TIMEOUT_SECONDS` из окружения; ключ не логируется.
- `api/routers/openai_api.py` — REST-адаптер `POST /api/openai/chat/completions`; сетевой вызов выполняется вне event loop. Endpoint не требует клиентского токена и должен быть доступен только из доверенной сети.
- `templates/dashboard.html` — форма отправки запроса с настройкой температуры и максимальной длины ответа.

Для прямого вызова из Python используй `modules.openai_api.chat_completion(messages, model=..., temperature=...)`. `OPENAI_BASE_URL` можно настроить на сервер OpenAI или совместимый API. Ключ провайдера хранится только в `.env` на сервере.

### `modules/vilmed/`

- `overspam.py:overspam_vilmed` — обработка таблицы overspam.
- `category_menu.py:update_cat_menu_vilmed` — обновление листа меню категорий.
- `api/routers/vilmed.py` — HTTP-адаптер для операций Vilmed.

### `modules/site_tools/`

- `bar_tags.py:link_selection_bar_tags` — основная функция обработки bar tags.
- `open_links.py:open_links_in_browser` — открытие переданного списка ссылок в системном браузере; интерфейс предоставляется через API и шаблон, отдельное администрирование функции не требуется.
- `update_sheet_bar_tags.py:main` — отдельный процесс обновления таблицы bar tags; перед повторным использованием проверь его входы, побочные эффекты и фактический способ запуска.
- `api/routers/site_tools.py` — HTTP-адаптеры операций с bar tags и ссылками.

Существующий код развивается неравномерно: не все старые функции уже оформлены как самостоятельные модули с полным контрактом. При добавлении нового функционала следуй правилам `AGENTS.md`, не копируя автоматически устройство legacy-файлов.

## Общие компоненты

- `shared/phrase_import.py:parse_phrases` — разбор фраз из текста или XLSX.
- `shared/temp_storage.py:manage_temp_dir` — создание, получение и удаление временных каталогов.
- `shared/log_stream.py:run_with_log_capture`, `stream_session` — захват вывода задачи и передача логов через SSE.
- `shared/link_checker.py:check_link` — проверка доступности ссылки.
- `shared/directory_cleanup.py:clear_directory` — очистка содержимого указанного каталога.

Перед созданием утилиты проверь, действительно ли она нужна нескольким возможностям. Если логика относится только к одной возможности, оставь её в соответствующем пакете `modules/`.

## Поток вызова

1. `main.py` создаёт приложение и подключает `api.routers.router`.
2. `api/routers/__init__.py` собирает отдельные роутеры страниц, системных функций и функциональных пакетов.
3. Роутер проверяет и преобразует HTTP-ввод, затем вызывает публичную Python-функцию функционального пакета или общий сервис.
4. Кодовый сценарий (когда он появится) вызывает те же Python-точки входа напрямую, без FastAPI.
5. Общая инфраструктура из `shared/` подключается по необходимости; она не должна содержать бизнес-логику конкретного сценария или продукта.

Для XMLRiver конкретная цепочка выглядит так: `api/routers/xmlriver.py` → `modules/xmlriver/service.py:run_module` → `modules/xmlriver/registry.py` → функция операции в `modules/xmlriver/` → `modules/xmlriver/export.py`.

## Как добавлять функциональность

### Новый функциональный модуль

1. Создай пакет `modules/<capability>/` с понятным именем.
2. Реализуй основную операцию как публичную Python-функцию с ясными входами, результатом и обработкой ошибок; не импортируй FastAPI в ядро.
3. Если нужен UI/API, добавь или расширь роутер в `api/routers/`. Роутер должен вызвать ту же функцию, доступную сценарию, а не копировать её бизнес-логику.
4. Подключи новый роутер через `api/routers/__init__.py`, если он отдельный.
5. Добавь офлайн-тесты на логику и контракт; внешние сервисы подменяй на границе вызова.

### Новая общая утилита

1. Создавай её в `shared/` только при реальном повторном использовании или явно общей инфраструктурной роли.
2. Сохраняй независимость от FastAPI и от конкретного продуктового сценария.
3. Дай имя, описывающее действие или ответственность, и проверь существующие компоненты на дублирование.

### Новый сценарий

1. Создай сценарий в `scenarios/` как последовательность вызовов публичных функций модулей.
2. Не помещай его orchestration-логику в `shared/` и не вызывай HTTP-маршруты из Python-кода.
3. Добавь тесты, подменяя внешние API и проверяя передачу данных между этапами.
4. Добавляй сценарий в реестр только если реестр реально используется вызывающим кодом; пустой `scenarios/registry.py` сам по себе не является работающим механизмом запуска.

## Проверки

- Автоматические тесты: `python -m unittest discover -s tests -p 'test*.py'`.
- `tests/run_test.py` — ручной XMLRiver-запуск с внешним API, а не автоматический тест. Не запускать его без явной необходимости и корректной конфигурации окружения.
- После изменения публичных точек входа обновляй эту карту и тесты вместе с кодом.
