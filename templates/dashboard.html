XMLStock

Учётные данные задаются на сервере через XMLSTOCK_USER и XMLSTOCK_KEY. Ответ API показывается как текст.

Поля Яндекс XML Proxy
  • Поисковый запрос — обязательная фраза до 400 символов; поддерживаются операторы вроде site:, mime:, lang: и date:.
  • Регион (lr) — ID региона поиска, например 213 для Москвы. Страница — номер страницы выдачи с нуля.
  • Домен — доменная зона Яндекса (ru, by, kz, com.tr); Устройство — тип устройства, для которого запрашивается выдача.
  • Результатов (groupby) — размер выдачи на странице, от 10 до 100. Сортировка — по релевантности (rlv) или времени (tm).
  • Фильтр — уровень фильтрации (moderate, none или семейный strict). Исправление опечаток — исправлять запрос (0) или искать точное совпадение (1).
  • HTTP-метод — отправка запроса методом GET или POST. Ответ этого инструмента всегда в формате XML.
Поля Яндекс Live
  • Поисковый запрос — обязательная фраза до 400 символов. Режим (tbm) — обычная выдача или поиск картинок/видео; Turbo включает ускоренный режим с выдачей до 50 результатов и тарифицируется отдельно.
  • Устройство — desktop или mobile. Регион (lr) — ID региона поиска. Страница — номер страницы, начиная с нуля.
  • Реклама (ads) — показывать или скрыть рекламные блоки. Похожие запросы (related) — включить или выключить блок «Люди ищут».
  • Период (within) — ограничить результаты сутками, двумя неделями или месяцем; этот параметр действует только для XML и JSON.
  • Подсветка (hlword) — включить или отключить выделение слов запроса тегом <hlword>. Формат — XML, JSON или HTML; HTML доступен только в режиме Turbo.
Поля Google XML Search
  • Поисковый запрос — обязательная фраза до 400 символов; поддерживается оператор site:. Регион (lr) — ID региона, который сервис сопоставит с регионом Google.
  • Устройство — desktop или mobile. Тип поиска (tbm) — обычная выдача, картинки, новости или видео.
  • Период (tbs) — быстрый выбор периода: сутки (qdr:d), неделя (qdr:w), месяц (qdr:m) или год (qdr:y). Поле ниже позволяет указать этот параметр вручную, например диапазон дат в формате cdr:1,cd_min:MM/DD/YYYY,cd_max:MM/DD/YYYY.
  • Язык (hl) — язык интерфейса/результатов, например ru или en. Связанные блоки (related) — включить блоки вопросов и запросов по теме.
  • Скрытые результаты (filter) — включить похожие друг на друга результаты, обычно скрываемые Google. Safe Search — режим фильтрации контента: on строгий, off выключен, active размывает контент.
  • AI Overview (ai) — запросить ИИ-ответ; включение тарифицируется дополнительно и может увеличить время ответа. Формат — формат ответа XML, JSON или HTML.
Можно выбрать готовый период выше или ввести полный параметр tbs для диапазона.
Поля Яндекс Wordstat
  • Запрос — фраза до 400 символов; не нужен только при выборе regionsTree. Тип данных (pagetype) задаёт результат: words — популярные фразы, history — динамика, regions — статистика по регионам, regionsTree — дерево регионов.
  • Число фраз (groupby) — сколько фраз вернуть (1–2000); используется только для words. Период (period) — интервал группировки истории: день, неделя или месяц; относится к history.
  • Устройства — фильтр устройств: все, desktop, mobile/phone или tablet; можно перечислить несколько через запятую.
  • Дата начала и Дата окончания — границы периода для history в формате ДД.ММ.ГГГГ.
  • Регионы — список ID через запятую (до 100), all для всех; отрицательный ID исключает регион, например -213. Распределение регионов — все элементы, только города или только крупные регионы; параметр применяется к regions.
XMLRiver

Выбери один способ ввода: вставь фразы по одной на строку или загрузи XLSX с заголовком столбца phrase.

  • Textarea: для каждой фразы собираются базовая частота и фразовая (запрос в кавычках). В отчёте будут столбцы phrase, total_value, phrasal_value.
  • XLSX без чекбокса: собираются обе частоты, результат выгружается в те же три столбца.
  • XLSX с чекбоксом «Сбор только фразовой частоты»: отправляется только запрос в кавычках, а phrasal_value добавляется последним столбцом исходной таблицы.

Инструменты работы с проектом VILMED
Для правильной работы таблица должна быть скачана из админ-панели VILMED. Обязательно должен отсутствовать столбец «Разделы», так как он объединяет ячейки в таблице. Также таблица должна содержать следующие столбцы: "Название", "Символьный код", "Детальное описание", "ID", "Артикул", "Комплектация", "Характеристики". Остальные столбцы будут проигнорированы и не попадут в конечный результат.
